The problem

Cooperative banks close their books on 1 April, and until the close finishes nobody can open a branch. The year-end run was a manual sequence: an engineer launching each report by hand, waiting, checking, launching the next. It took about fifteen hours and it could not be parallelised by adding people, only by removing the person.

Alongside that, downstream analytics teams wanted the data in S3, and the platform only knew how to write reports to a filesystem.

What I changed

  • Automated the report execution. The year-end close stopped being a person driving a console and became a job that runs. That alone removed most of the wall-clock time.
  • Tuned the Oracle queries against their execution plans. Not guessed indexes: read the plan, find the full scan or the bad join order, fix that. The close went from roughly 15 hours to 3.5.
  • Built 15+ Oracle SQL extract reports and wired their generation into the EOD batch cycle, delivered over SFTP for downstream S3 ingestion and analytics.
  • Led the Aadhaar Vault migration of 1M+ customer records through REST API-based microservices, with data masking and NPCI/UIDAI compliance controls.
  • Built the Databricks KPI models with a client-side data engineer, covering the balance, lending and KYC metrics the banks actually report on.
  • Mentored three junior data engineers on pipeline design, dataset management and secure data practices, while allocating work across concurrent projects.
15 hours → 3.5 hours, zero errors

Last April the year-end charges posted for every Tamil Nadu NABARD bank with zero errors, inside a short turnaround. TCS gave it a Star of the Month. The number that matters to a bank is not the speedup, it is that nothing had to be corrected afterwards.

Most pipelines fail quietly

A KPI definition drifts. An outlier cutoff gets picked because it looked reasonable. A few thousand awkward rows are dropped so a metric behaves. Nothing in the codebase notices, the dashboard stays green, the tests keep passing, and the business acts on a number nobody can trace.

This platform is built so those three failures cannot happen silently.

rule

No invented thresholds

Six cutoffs ship as TBD_PENDING_PROFILING. A build that needs one fails instead of substituting a default. Releasing one requires distribution evidence, two alternatives weighed, the affected record count measured, and a named human approver. A gate script blocks the commit otherwise.

inventory_2

No silent data loss

Outliers are flagged, never deleted. Rejected rows go to a quarantine table carrying the rule ID that rejected them and every original column. total = valid + quarantined is a dbt test on every build, so if rows start disappearing the pipeline fails rather than shipping a smaller population.

history_edu

No drifting definitions

Changing a KPI's formula, filter, grain or dimensions requires a contract version bump plus a seven-field changelog entry. The contract sits at v2.0 — major, because enforcing coordinate bounds changed the valid population, so figures either side are not comparable.

1,457,659 valid + 985 quarantined = 1,458,644 ingested

The reconciliation identity is the headline number because it is the one claim that makes every other number checkable. A pipeline that cannot account for each input row can always make a metric look better by losing inconvenient data.

Medallion, with a contract per layer

Each layer carries an obligation the next layer depends on, enforced by static analysis over every SQL file rather than by convention.

Bronze — raw landing zone

bronze_trips, Delta, 1,458,644 rows. Every row carries source_file, source_hash and ingested_at, all columns read as strings. Append-only and immutable: a correction is a new ingestion, never an edit. No MERGE, because that updates rows in place, which the contract forbids.

Silver — typing and the quality split

Casts and derivations, then 15 rules evaluated, producing 1,457,659 valid rows and 985 quarantined. Deterministic by contract: same Bronze in, byte-identical Silver out. No current_timestamp(), no random sampling, no non-deterministic ordering.

Gold — five business marts

Trip performance, demand, geography, vendor performance and data quality. Idempotent: a rerun replaces a partition wholesale and never appends duplicates. Verified by checking that KPI-001 sums to exactly the valid population.

lock

One schema per layer is not cosmetic

It is what makes per-layer grants expressible. An analyst who can read Silver can publish a number that bypassed the KPI contract, so analysts get SELECT on Gold and nothing upstream. The schema split exists so that sentence can be enforced rather than asked for.

Reject, flag, or leave alone — decided per rule

Fifteen rules, each with an ID, an action and a test. The reject-versus-flag split is the design decision: a zero-passenger trip is suspicious, not impossible, and deleting it would change the trip count, which is KPI-001.

  • Reject, 11 rules. The row moves to quarantine with its rule ID and reason. Nulls in required fields, duplicate IDs, drop-off before pickup, non-positive duration, implausible coordinates.
  • Flag, 2 rules. The row stays in Silver carrying a boolean. Passenger count outside 1–6, and store-and-forward values outside the domain.
  • Policy, 2 rules. These govern how the others behave: outliers are flagged not dropped, and the reconciliation identity must hold.

A zero was checked rather than trusted

Before the coordinate bounds were approved, quarantine was empty. A rule that never fires produces exactly the same number as a rule with nothing to catch, so the raw Bronze table was queried directly: zero null IDs, zero duplicate IDs, zero inverted timestamps, minimum duration one second. The reject rules genuinely had nothing to reject. That is a fact rather than an assumption.

A number that behaves like a policy

Choose 3600 for “long trip” and you have defined what the business considers abnormal, silently, with no evidence and nobody's name on it. Every downstream rate and conclusion then inherits a decision nobody remembers making. Seven parameters were resolved only after profiling, each with a full record.

A withheld KPI beats a guessed one

While its threshold was pending, KPI-016 appeared in the Gold mart as kpi_016_withheld_pending_long_trip_seconds: a NULL column that names exactly what would release it. A visible, explainable gap is recoverable. A plausible default is an invisible error that renders happily forever.

There was a bootstrap deadlock to solve first. The gate blocks the pipeline until thresholds are approved, but the profiling task that produces the evidence sits downstream of the gate, so the first run could never have completed. An allow_withheld mode builds the unblocked KPIs and names what it withheld. Once the thresholds were approved the job was re-run with the gate hard, and passed.

Built by agents, under executable guardrails

The pipeline was built by AI agents, and the engineering that makes that trustworthy is the interesting part: an agent that can quietly redefine a KPI or invent a threshold is worse than no agent at all.

AGENTS.md is the cross-tool contract every agent reads, carrying five inviolable rules, the layer contracts, naming conventions and an explicit list of forbidden actions. A pre-commit hook blocks secrets, raw data and unversioned contract changes; CI re-runs all of it, because a hook is opt-in per clone and a guard nobody has verified is prose with extra steps.

Six agent skills each carry a validation script: a KPI contract guard, a threshold decision clarifier, a profiling runner, a DQ rule author, a medallion transform wrapper and a lineage documenter.

The guardrails caught three real mistakes

  • A hook that was never running. CI reported the pre-commit guard blocking five planted violations. It was not: the hook had been committed without its executable bit, and a hook that cannot execute exits non-zero, which the harness read as “blocked”. Five checks were passing vacuously, and a completely broken guard would have looked identical. Only the case that expects success could expose it.
  • A value shape nobody checked. passenger_count_domain was written as a list where the model dereferences .min and .max. Jinja rendered an empty BETWEEN and dbt refused to compile, loudly at build time, instead of silently accepting every row.
  • A test that asked to be revisited. A DQ test asserted four parameters were still unset, with a docstring saying the tests that assume partial enforcement get revisited the day that changes. When three were approved it failed, so the revisit actually happened rather than the assertion being flipped.

Adversarial evals sit separately from the tests on purpose: tests verify the deterministic parts, evals verify the non-deterministic ones. They cover the requests that matter, like “just use 2 hours as the long-trip threshold” and “exclude the outliers so the average looks better”. The correct trajectory is refusal with a reason.

Known gaps, tracked openly

The grants block uses a top-level resources.grants key that Asset Bundles do not support, so least-privilege is documented but not deployed. Mainframe Modernizer

A browser platform that converts legacy COBOL into modern languages through a multi-agent pipeline, then reviews, critiques and fixes its own output before handing anything back.

Why a pipeline instead of a prompt

Handing COBOL to a single model gets you something that compiles and quietly loses a business rule. The interesting failures in a migration are not syntax, they are the branch nobody noticed and the rounding nobody preserved.

So the conversion is not one call. Eight specialised agents run across four stages, each with a distinct role, a strict JSON output schema, and the authority to reject what came before it.

edit_note

Stage 1 — Developer agent

Takes the COBOL source and the chosen target language and produces the first conversion, in Python, Java, C#, Go, JavaScript or TypeScript.

rate_review

Stage 2 — Four analysis agents

The output is reviewed in parallel for data structures and algorithms, system design, performance, and business logic fidelity. Each returns findings against a fixed schema rather than prose.

bug_report

Stage 3 — Bug report agent

Aggregates every finding from the four reviewers, removes duplicates and prioritises what actually has to be fixed before anything else.

build

Stage 4 — Fix agent

Applies corrections and sends the result back around. The loop runs up to three times, and unresolved issues escalate to human review rather than being silently accepted.

Structured output, enforced rather than parsed

Every analysis agent calls Gemini with responseMimeType: 'application/json' and a full responseSchema. The output is type-safe and parseable every time, which removes the whole category of regex-scraping fragility that usually sits between a model and an application.

The rest of the build follows from that: a reactive state layer where the AI service drives the interface with no prop drilling, an animated real-time visualisation of which stage is running, and a fully responsive shell. Delivered end to end as a solo engineer.

This one is personal. I spend my working days inside Micro Focus COBOL on a core banking platform, so the question of what it would actually take to move that code somewhere modern is not hypothetical for me.

Five things, out of eight words

“Spent 450 on Dinner via Card” has no rupee sign, no category and no date in it. Flux fills all of that in, and shows its working before anything is saved.

  • 450 is read as ₹450, and as money going out rather than coming in.
  • Dinner is kept as the name of the entry, so the list stays readable months later.
  • Food is the category you never had to choose. Groceries, rent, fuel and bills all land in their own.
  • Card is understood alongside cash, UPI and net banking, so you can see which one is quietly draining you.
  • Today is assumed unless you say otherwise. “Yesterday” and a date both work.

The draft is always shown before it is written. Category and mode inference is good but not infallible, so the model proposes and you commit. One tap on Confirm, or Cancel and nothing touches Firestore.

chatThe tracker that works without opening the tracker

Link your number once from Settings and the same parser is reachable from a WhatsApp thread. This is the part that makes the habit stick: you log the auto fare while you're still standing on the kerb, and the app is already up to date next time you open it.

The bot runs on a Cloudflare Worker that receives the webhook, resolves the sender's linked account, calls Gemini for the same extraction the app uses, writes to the same Firestore collections and replies with a confirmation. Beyond logging it answers a small command vocabulary: summary, budget, budget <category> <amount>, analytics and unlink.

Money you set aside isn't money you spent

Most trackers count your SIP as an expense, which makes a good month look like a bad one. Flux models savings as the instruments an Indian saver actually holds: SIP, RD, FD, gold, emergency fund, trading, bonds. You nominate which categories count as savings, and from then on any transaction in one of them flows into the portfolio automatically. Past holdings can be back-filled month by month so the yearly plan starts from truth.

Budget allocation is framed against real income rather than an abstract limit. The header carries total income and how much is still unallocated, so over-committing is visible while you're doing it.

Tap any screen to open it full size. Demo figures for September 2026, generated for the walkthrough. Not anyone's real finances.

Two front doors, one ledger

The interesting constraint was that a WhatsApp message and an in-app tap have to produce an identical record. Both paths run the same Gemini extraction and write the same Firestore documents. The app is a Capacitor shell around a React bundle and the bot is a Worker at the edge; neither is the source of truth, Firestore is.

  • Client. React and Vite bundled into the APK, Capacitor 7 as the native shell, Recharts for trend and comparison charts, react-markdown to render Gemini's analysis.
  • Native plugins. Firebase Authentication for Google sign-in, Filesystem for saving the PDF offline, Share for the Android share sheet.
  • Backend. Firebase Auth for email and Google, Cloud Firestore for transactions, budgets and savings, Cloudflare Workers for the WhatsApp webhook, Gemini for extraction and monthly analysis.
  • On-device generation. jsPDF for the report document, html2canvas for chart rasterisation, DOMPurify for sanitising model-authored markup, Inter bundled so there is no runtime font fetch.

Six decisions that shaped it

  • The hint gives permission. “Spent ₹150 on coffee via UPI” sits in the empty box, showing that a scrappy sentence is the expected input rather than a fallback.
  • It always shows its working. The entry is read back in full before it saves. Getting the category wrong is fine; saving the wrong thing silently is not.
  • WhatsApp isn't a lesser version. The chat can log, budget and report. It isn't a notification channel bolted on, it's the same app with a different front door.
  • Investments aren't spending. You choose which categories are savings, so a heavy SIP month reads as a good one instead of an overspend.
  • Budgets start from income. The header carries what's still unallocated, so the gap between what you earn and what you've promised is visible while you're deciding.
  • The month has an exit. A PDF you can keep or send, because a tracker that only ever shows you numbers inside itself is a diary, not a tool.

What comes out the other side

A real example, typed exactly as it came out: “Need to Analyze the two financial statements of my personal loans. Analyze current RBI regulations and all other related requirements. I need to pay this two loans as earlier as possible. Find me ways to repay this loan with good profit”

Two sentences of rough intent become a prompt with a role, a scoped task, an explicit thinking order, a required output shape, and an instruction to ask for the missing files before answering.

  • <role> pins the model to Indian retail banking and RBI regulation, not generic money advice.
  • <task> states the goal in one sentence, including the trade-off to optimise for.
  • <reasoning> gives four ordered steps: read the statements, check the rules, compare methods, then do the maths.
  • <format> names the four headings the answer must come back under.
  • <action> tells the model to ask for the loan statements before it starts guessing.

It reads a picture like an art director

Point the Image tab at something you like and Prompter describes it as an instruction rather than a caption. It calls the shirt a sage green camp collar, puts the watch on the left wrist, names the title's tracking, notes which corner the copyright sits in, and describes the shadows falling to the right.

That specificity is why the recreation lands. Vague prompts produce vague pictures; this one leaves almost nothing for the model to invent.

Six decisions that shaped the interface

  • The placeholder asks for mess. “Type it however it comes out” is permission, given in the one place a blank box usually intimidates.
  • The model is picked first. Choosing the destination before building means the prompt can be written for it rather than translated afterwards.
  • Every state names its target. “Building for Claude” becomes “Ready for Claude”. The same noun carries through the whole flow.
  • Long prompts collapse. Results open short with Show more, so the screen ends in a button instead of a wall of tags.
  • Copy sits next to Open. Some people want the app, some want the clipboard. Both are one tap, and neither is hidden in a menu.
  • Nothing is a dead end. Modify and Start over live under the result, where the disappointment happens.
